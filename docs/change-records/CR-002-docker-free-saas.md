# CR-002：SaaS 与无 Docker 发行目标

状态：Approved

批准日期：2026-09-03

批准来源：项目负责人明确要求最终交付物为 SaaS 和可运行程序，正式运行不得依靠 Docker。

## 决定

1. 最终交付必须包含可部署的 SaaS 服务和版本化的可运行服务端发行物。
2. 正式安装、启动、升级、回滚与验收路径不得要求 Docker CLI、Docker daemon 或 Docker Compose。
3. Docker 只可用于本地开发、Huly 上游对照和隔离回归，不得成为唯一构建或运行路径。
4. “可运行程序”在本变更中指带浏览器产品入口的服务端发行包；不承诺单一桌面可执行文件。桌面客户端如需立项，另行决定操作系统、自动更新和签名要求。
5. 第一目标平台为 Linux x64 SaaS 服务端；开发机可运行同一份无原生扩展的 Node.js 发行物。
6. 多租户身份、数据隔离和持久化策略必须在进入正式 SaaS 集成前形成独立 ADR，不能由当前进程内存原型代替。

## Phase 0 调整

插入两个部署闸门，P0-05A 暂后移：

- `P0-ND-01`：产出 Product API、Worker 和自包含浏览器入口的 Node.js 24 发行包、启动器、SHA-256 校验和与无 Docker 冒烟证据。
- `P0-ND-02`：在未安装 Docker 的干净 Linux x64 环境完成安装、启动、登录、图谱 → Task → File、重启持久化、升级和回滚。

P0-02、P0-04、P0-05 的 Compose 证据继续作为 Huly 适配可行性证据，但不再是正式部署证据。ADR-001 的生产目标平台结论相应重开。

## P0-ND-01 验收

- `pnpm start` 不调用 Docker，启动浏览器入口、Product API 和 Worker。
- `pnpm build:native` 生成版本化 `tar.gz`、POSIX 启动器和 `SHA256SUMS`。
- 从临时目录解包运行，健康检查、HTML 入口、六节点查询和任务创建成功。
- 冒烟环境中的伪 `docker` 命令未被调用。
- 制品仍明确标注为可行性产物，不冒充生产 SaaS。

## 未完成且不得隐含为已交付

- 当前默认 Domain Store、Task/File Adapter 与 Worker 状态仍在进程内存中，重启不持久。
- 尚未提供 SaaS 登录、租户开通/隔离、TLS、持久数据库、对象存储、备份恢复、可观测性或水平扩展。
- 完整 Huly 服务尚未形成受支持的原生进程发行物；最终是否继续使用 Huly Task/Identity 仍等待后续 ADR。
- 当前发行包依赖 Node.js 24；是否内嵌运行时在 P0-ND-02 前决定。

## 正式文档同步范围

PRD、FC-016、技术架构、数据与权限、MVP Backlog、测试计划、Huly 上游同步规范和发布运行手册都必须吸收本决定。仓库内以本记录作为已批准产品决定；源文档版本同步完成后再提升 PRD/FC 版本号。
