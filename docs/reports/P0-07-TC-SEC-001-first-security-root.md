# P0-07 / TC-SEC-001 首个敏感根与首管理员

- 日期：2026-09-04
- 状态：通过子切片验收；P0-07 总项保持进行中
- 产品依据：FC-013、A5-02、TC-SEC-001
- 架构依据：CR-003、ADR-003、ADR-004、ADR-006、ADR-008

## 本切片交付

- 新增正式 `SecurityDomain` 与逐用户 `SecurityGrant`。首次把普通节点设为敏感根时，操作者必须是有效项目经理；首名 `manage_access` Grant 与域、节点版本、安全纪元、最小事件、Outbox 和幂等回执在一个本地事务内提交。
- 新增 `POST /api/nodes/{nodeId}/security-domain` 与同源浏览器客户端契约。请求要求稳定幂等键、节点期望版本和审计理由；重试只产生一个域、一名管理员和一个安全域事件。
- 安全域 ID 只由服务端从租户、主体与幂等键派生，忽略客户端同名字段，避免利用碰撞错误探测其他敏感域或遗留域 ID。
- 当前成员、Principal 和已有域权限先于幂等回放重新校验；撤权后不能利用旧回执继续获得成功结果。无项目权限与不存在节点统一返回 404，不泄漏节点是否存在。
- Product API 在构造节点、Task 和 Asset DTO 前逐对象鉴权。新域中没有 Grant 的普通项目成员看不到敏感根、任务或文件元数据。
- SQLite schema v4 与 Memory 实现同一持久化端口；关闭重开后仍保存域、首名管理员、节点安全域和幂等结果，未知未来 schema 继续拒绝启动。
- 新建敏感根只接受无后代、无任务、无文件的空叶节点。转换后创建的 Task/Asset 继承该 `securityDomainId`；普通建节点不能直接指定域，也不能在敏感父节点下创建可能保持公开的后代。
- 租户内任何 Node、Task 或 Asset 曾引用过的旧域 ID 都不能被新正式域复用，避免 v3 授权语义被劫持。v3 `membership.securityDomainIds` 只兼容 `view`，绝不提升为 `contribute/edit/manage_access`。
- 每次事务在权限判定处读取当前时间；文件外部存储结束后的最终事务重新取时间并复验，避免短时 Grant 在等待或上传期间到期后仍写入。

## 明确未完成

本报告只接受 `TC-SEC-001` 的空叶节点首根链路，不能据此关闭 P0-07：

- 没有成员配置 UI/API、Grant 新增/降级/撤销命令、追加式安全审计和可查询授权名单。
- 没有“始终至少一名 `manage_access`”的 Grant 变更守卫；任何 Grant 修改入口在 `TC-SEC-003` 完成前不得开放。
- 没有普通后代继承写入、非空子树迁移、旧域∩新域逐对象判定或嵌套域最小能力；这些归入 `TC-SEC-002`。当前用空叶限制和敏感父节点拒绝新增后代来 fail-closed。
- 没有覆盖搜索、通知、实时、ZIP、导入、批量操作等全部通道；安全域事件进入任何通用消费者前还需验证接收方 ACL。
- 没有完成文档要求的整套固定权限身份，也未解除非 loopback 监听闸门。
- 没有完成 P0-05A 的模板角色槽位、节点负责人回退、验收 UI、Deliverable/Evidence 和节点完成守卫。
