## 目标

在现有 ProjectNode、Asset、Membership、Grant、Node Owner、TemplateRoleSlot/ProjectRoleBinding 和原子 Event/Outbox/Receipt 基线上，完成第一条可验收的交付物纵向闭环：交付物要求绑定文件型证据，提交后由快照验收人或当前合格项目经理接受，或者由当前合格项目经理填写理由豁免。

本切片必须证明 `DeliverableRequirement` 与 `EvidenceLink` 不会因普通 Asset 引用而放宽 owner node 或 Security Domain 权限；不得假装尚未实现的 ProcessRecord 已可用。

## 直接契约

1. `DeliverableRequirement` 固定 tenant/project/owner_node/security_domain 与 epoch，字段至少包含 requirement key、title/description、required、accepted source types、min count、reviewer、状态、accepted/waived actor/time/reason 和 version。
2. 状态词汇固定为 `pending/submitted/accepted/waived/evidence_due`；本切片只实现文件证据的 `pending|evidence_due → submitted → accepted` 和 PM `→ waived`。不得自行新增常驻状态。
3. `EvidenceLink` 只允许连接同 tenant、同 project、同 owner_node、同当前 security_domain/epoch 的证据。文件必须可用且未逻辑删除；隔离、失败、上传中或损坏数据均 fail closed。
4. 提交必须满足 requirement 的 `min_count` 个唯一有效文件证据，并尊重 `accepted_source_types`。ProcessRecord 尚未实现时必须稳定拒绝该来源，不能伪造支持。
5. 交付物提交：当前 active user + active project Membership，并满足项目经理、负责节点的 Node Owner 或负责内容提交人的既有授权边界；实现不得创建新的 RBAC/Grant 能力。如现有模型不能无歧义表达“负责内容提交人”，本切片只开放 PM 与 Node Owner，不得自行放宽到所有成员。
6. 接受：快照 `reviewerPrincipalId` 当前仍合格且对所属安全域有权，或当前 active 项目经理且具有目标域所需权限。豁免：仅当前 active 项目经理，且 reason 去空白后非空。
7. ProjectRoleBinding 本身不授予 Membership、Grant、ACL 或最后管理员资格；本切片不做隐式 reviewer 推导。Requirement 初始化必须接收并验证明确 reviewer 快照，或仅供未来模板 provisioning 的窄受守卫入口；不得暴露通用底层写旁路。
8. 权限时间使用 persistence trusted clock；命令 `occurredAtUtc` 只作业务记录输入，不能用于回拨鉴权或过期 Grant。
9. 每个成功命令在一个本地事务内保存 aggregate、追加式 Evidence/action fact、DomainEvent、Outbox、Receipt。重试、并发和故障注入不得产生重复链接、重复动作或部分写入。
10. 幂等回放必须重新授权，并核对权威 requirement/node/domain/epoch/evidence 与完整载荷指纹；同键异载荷稳定拒绝。无权与不可知对象维持既有 404 防枚举语义。
