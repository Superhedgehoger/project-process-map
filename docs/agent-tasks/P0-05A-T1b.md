## 目标

把已验收的三个权威底座接成 Task 验收人解析链：显式验收人 → 项目模板角色槽位 → 当前节点负责人。所有候选人在写入 Task 快照前都必须重新验证 active Principal、active ProjectMembership 与目标对象当前 Security Domain 权限；最后没有合格人时原子返回 `REVIEWER_REQUIRED`。

## 已确定规则

1. 合格的显式验收人优先。
2. 槽位不存在、未绑定、成员失效或没有目标安全域权限时，继续回退到节点负责人。
3. 节点负责人仍不合格时，原子返回 `REVIEWER_REQUIRED`，不得创建部分 Task/Event/Outbox/Receipt。
4. ProjectRoleBinding 不授予 Membership、Grant、ACL 或最后管理员资格。
5. 解析结果保存为 Task 的单一 `reviewerPrincipalId` 快照；后续权限变化不得静默改写既有 Task。
6. Task 创建契约提供可选 `reviewerRoleSlotKey`，由调用方显式指定本 Task 使用的项目角色槽位；不允许根据 slot name、description、列表顺序或隐藏默认值推断。
7. `reviewerPrincipalId` 非空且当前合格时直接获胜；此时 `reviewerRoleSlotKey` 不参与候选解析，但仍属于命令载荷与幂等指纹。显式 reviewer 不合格时不得通过槽位掩盖错误。
8. `reviewerPrincipalId` 为空时才读取 `reviewerRoleSlotKey`。字段为空、槽位/绑定缺失或槽位候选全部不合格时继续回退 Node Owner。
9. `requiresAcceptance=false` 时不得提供 `reviewerRoleSlotKey`，与现有禁止 reviewer 的规则一致。

## 当前产品规则缺口

已全部关闭。产品负责人批准：

- 一个项目槽位存在多名当前合格候选人时，复用现有 canonical Principal ID 严格排序并选择最小者。不得改为 locale 排序、输入顺序、随机、轮询、工作量均衡或其他隐式状态算法。
- Task 创建契约新增可选 `reviewerRoleSlotKey`，显式标识本 Task 使用的项目角色槽位；不使用保留默认键，也不要求先新增模板 Task 聚合。

该决定只在过滤掉失效 Principal、失效 Membership 与无目标安全域权限的候选人后应用；若槽位层没有合格候选人，继续回退到节点负责人。

## Expected Scope

- `packages/application/src/tasks`：解析服务及 Task 创建受守卫接入；当前决定不扩展既有 reviewer 改派命令。
