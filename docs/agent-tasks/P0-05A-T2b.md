## 目标

在已完成的 `P0-05A-T1a/T1b`（Task 验收闭环与三级验收人解析）和 `P0-05A-T2a`（DeliverableRequirement / EvidenceLink 文件证据提交与接受/豁免）基线上，实现 `ProjectNode` 领域生命周期状态机与权威节点完成守卫：
仅当当前节点的所有必需 Task 均已完成/验收、且所有必需 `DeliverableRequirement` 均处于 `accepted` 或 `waived` 状态时，才允许有权角色（当前 active 项目经理或负责该节点的 Node Owner）将节点推进至完成状态（`completed`）；任何未完成前置项必须原子拒绝节点完成操作，并在 Memory 与 SQLite 双后端提供一致的 CAS 版本保护、事务边界、DomainEvent/Outbox/Receipt 与幂等重放机制。

## 直接契约

1. **节点状态模型**：`ProjectNode` 聚合增加显式状态（如 `planned | in_progress | completed`），记录初始状态、完成时间（`completedAtUtc`）与完成操作者（`completedByPrincipalId`）。
2. **节点完成守卫检查**：
   - 操作权限：当前 active user + active project Membership，且为当前 active 项目经理或负责该节点的 Node Owner；具备目标节点安全域权限；鉴权使用 persistence trusted clock。
   - 任务完成守卫：当前节点下所有未软删除的 Task，必须全部满足完成条件（免验任务 `lifecycleState = completed`，必验任务 `reviewState = accepted`）。任何处于 `todo`、`in_progress`、`pending_review`、`rejected` 的 Task 均导致节点完成拒绝（`NODE_TASKS_NOT_COMPLETED`）。
   - 交付物完成守卫：当前节点下所有未软删除的 `DeliverableRequirement`，凡 `required = true` 者，其状态必须为 `accepted` 或 `waived`。任何处于 `pending`、`submitted` 或 `evidence_due` 的必需交付物均导致节点完成拒绝（`NODE_DELIVERABLES_NOT_SATISFIED`）。
3. **迁移与冻结保护**：安全域迁移活跃期（active/verifying）的节点完成保持既有逐对象权限交集与写冻结规则，fail-closed。
4. **事务与原子性**：节点完成命令在同一物理事务内持久化 Node 状态变更、追加完成 action/fact、生成唯一 DomainEvent、Outbox 消息与幂等 Receipt；任一故障注入点整体回滚，零残留。
5. **双后端持久化一致性**：Memory 与 SQLite 实现完全等价行为，SQLite 处理必要 schema 演进并保证 reopen / restart 数据一致。
