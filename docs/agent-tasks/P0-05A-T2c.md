## 目标

在 `P0-05A-T2a` 文件 Evidence 闭环、`P0-05A-T2b` 节点完成守卫和 ADR-007 Asset/Evidence 边界之上，实现：

1. Asset 被权威删除或隔离后，引用该 Asset 的 Evidence 立即失效；
2. 历史 Evidence、接受动作和审计事实继续保留，不以物理删除历史实现失效；
3. 受影响 DeliverableRequirement 按批准规则重新计算，并阻止失效 Evidence 被节点完成或项目完成/归档守卫当作有效交付物；
4. 本地 Asset / Binding / Deliverable / Event / Outbox / Receipt / Cleanup Job 遵守单事务原子边界，外部 Blob 清理继续异步可重试，清理失败不得复活逻辑删除的 Asset；
5. 在项目生命周期契约获批后，实现项目完成/归档状态机及权威守卫。

## 已批准直接契约

### A. Evidence 失效

1. `EvidenceLink` 保留为不可变提交事实；当前有效性由权威 Asset 状态与受控 Evidence binding 失效投影共同决定，避免双权威。
2. Asset 删除后立即不可下载；同一事务内失效引用它的所有 active evidence bindings，并追加失效 action/fact、DomainEvent、Outbox、Receipt 与 Blob cleanup job。
3. 增加 `available → quarantined`。该转换仅允许可信扫描/安全服务身份执行，必须提供去空白后非空 reason；隔离与删除产生相同的 Evidence 失效结果。
4. 删除仅允许当前 active PM 或负责 owner node 的当前 active Node Owner，且必须具有目标安全域权限并提供去空白后非空 reason；不得授予 uploader 一般删除权。
5. Deliverable 仅按有效且边界一致的 Evidence 重新计算；损坏、跨 tenant/project/node/domain/epoch 或已失效数据一律 fail closed。
6. 仅当剩余有效 Evidence 数量小于 `minCount` 时，非 waived Deliverable 转为 `evidence_due`。`waived` 不受 Evidence 变化影响。
7. `accepted → evidence_due` 时清空 canonical acceptance 字段；原接受事实和 actor/time/reason 只保留在追加 action/history 中，不得改写历史。
8. 已完成 ProjectNode 不自动重开；Evidence 失效后的实时不满足状态阻止后续 Project completion/archive。不得把历史 completed 事实伪装为从未发生。
9. 重新提交、接受、节点完成与删除/隔离并发时，以 CAS 和事务序列化保证只出现一个合法顺序；loser 零部分写入。

### B. 项目完成/归档

1. Project 生命周期至少分离 `completed` 与 `archived`；`archived` 是 `completed` 之后的独立终态，不得合并为单步归档。
2. 只有当前 active PM 可完成或归档 Project，并须通过项目及相关安全域的当前权限检查；命令时间不得用于鉴权回拨。
3. Project completion 要求全部未软删除 ProjectNode 已完成，并实时验证所有 required、未删除 Deliverable 仍为 `accepted | waived`，且 accepted Deliverable 的有效 Evidence 仍满足 `minCount`。
4. Project archive 除满足 completion 条件外，还要求无 active 安全域迁移、无未发布的项目范围 Outbox，以及无会继续改变项目权威状态或安全/恢复结果的 non-terminal project-scoped job；纯外部 Blob cleanup 失败不得复活 Asset，但其是否属于 archive blocker 必须由实现按“会否改变权威状态”判定并测试。
5. archive 后冻结普通产品领域写入；仅允许读取、审计、导出和明确的安全/恢复控制面操作。任何恢复操作不得隐式把 Project 改回 active；若未来需要 unarchive，另立产品决定。
6. completion/archive 均须提供 CAS、幂等重放、DomainEvent、Outbox、Receipt、Memory/SQLite parity 与故障注入原子回滚。
7. 已完成节点后续 Evidence 失效不自动重开节点；它使尚未执行的 Project completion/archive 失败。已 archived Project 后的强制安全隔离仍必须允许并记录审计事实，不自动 unarchive。

## Acceptance Criteria

- 删除/隔离后 Asset 立即不可作为有效 Evidence，历史链接与动作仍可审计。
- 受影响 Deliverable 严格按批准的 `minCount` / status 规则重算；重新提交可恢复闭环。
- 节点完成和项目完成/归档在执行时重新验证 Evidence 当前有效性，不能只信缓存终态。
- Asset、binding、Deliverable、Event、Outbox、Receipt、cleanup job 的本地写入原子；逐写入故障注入零残留。
- 外部 Blob 清理异步可重试，失败不改变逻辑删除和 Evidence 失效结果。
- 同键重放重新鉴权并绑定权威 Asset / Evidence / Deliverable / node/project 状态；同键异载荷拒绝。
- Memory/SQLite、schema upgrade/reopen、双连接竞态与损坏数据均保持 fail closed。
- 定向 Gate、`pnpm check`、diff check、artifact/JSON 校验、凭据扫描和独立 Codex R2 Review 全部 PASS 后方可 closeout。
